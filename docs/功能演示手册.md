# 无人机链路抗干扰测试平台·功能演示手册

> 适用范围：平台全部功能的现场演示。设备与连接看总章；逐功能演示看第 1–26 章（每章四件套：功能说明／所需设备与连线（便携档、全量档）／操作步骤（命令与参数）／预期现象）；现场意外看附录应急速查表。

### 0.3 连接方式（ASCII 图＋接线表）

**方案 A——默认演示态（sim 全流程，最常用）**：只需笔记本；B210 可不接（自动降级 sim 并如实标注）。

```
[笔记本] ── (无需任何射频连接；backend: auto/sim)
```

**方案 B——B210 真机（监测/注入演示，屏蔽盒口径）**：

```
                       ┌────────── 便携金属屏蔽盒 ──────────┐
 [笔记本]               │  [双频天线A](发射)    [双频天线B](监测) │
   │USB3                │      ▲                   ▲          │
   └── B210 CH1 ─MMCX转SMA─[30dB衰减器]──┘    B210 CH2 ───────┘
       （CH1 也可不接天线、直连 SMA 负载闭合，零空中辐射）
```

| 接口 | 线缆/部件 | 对端 | 说明 |
|---|---|---|---|
| 笔记本 USB3 口 | USB3 数据线 | B210 | 供电兼数据；插 USB3 口否则带宽不足 |
| B210 CH1（MMCX） | MMCX 转 SMA → **30dB 衰减器** → 双频天线A 或 SMA 负载 | 盒内 | 发射链必串衰减器（合规 ≤0dBm 口径） |
| B210 CH2（MMCX） | MMCX 转 SMA → 双频天线B | 盒内 | 监测天线，独立采集实际注入谱 |
| B210 GPS 口 | GPS/BD 有源天线 | 盒外窗口 | 时钟参考演示（可选） |

**方案 C——ESP32 WiFi 真链路（配合方案 B 的注入天线）**：

```
                       ┌────────── 便携金属屏蔽盒 ──────────┐
 [笔记本]               │ [ESP32#1(tx)] ⇄WiFi⇄ [ESP32#2(rx)]  │
   │USB(串口)           │     ▲干扰经盒内发射天线压制此链路▲    │
   └── ESP32#2 串口     └──────────────────────────────────┘
       （KPI 帧经串口上报：ESP,<seq>,<sent>,<err>,<retries>,<rssi>）
```

| 接口 | 线缆 | 对端 | 说明 |
|---|---|---|---|
| 笔记本 USB-A 口 | ESP32 USB 线 | ESP32#2（接收/上报节点） | 串口设备名 `/dev/ttyUSB0` 或 `/dev/ttyACM0` |
| ESP32#1/#2 | 各自 USB 供电 | 充电头/USB 集线器 | 发射节点无需串口 |

**方案 D——NRF24 真链路（复用两块 ESP32 作主控）**：

```
 [ESP32#1] ─SPI─ [NRF24L01#1] ⇄2.4G ESB⇄ [NRF24L01#2] ─SPI─ [ESP32#2] ─USB串口─ [笔记本]
            （发送+上报节点：PLOS/ARC 计数与 RPD 位随 NRF 帧上报）
```

| 接口 | 线缆 | 对端 | 说明 |
|---|---|---|---|
| ESP32 ↔ NRF24L01 | 杜邦线×6（3V3/GND/MOSI/MISO/SCK/CSN＋CE） | NRF24 模块 | 3.3V 供电，接线以固件 README 引脚表为准 |
| 笔记本 USB-A 口 | ESP32 USB 线 | ESP32#1（发送+上报节点） | 串口帧：NRF,<seq>,<sent>,<lost>,<retries>,<rpd> |

> 主机 USB 口分配建议：USB3 口固定给 B210；两个 USB-A 口给 ESP32 串口；其余接集线器。设备名以 `ls /dev/ttyUSB* /dev/ttyACM*` 实测为准。

### 0.4 主机环境启动（演示当天 3 分钟）

```bash
cd fn_work                                   # 一切命令的前提
.venv/bin/python -c "import fastapi, sigmf"  # 环境自检：无输出=依赖齐
ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null     # 串口设备枚举（接了 ESP32 才有）
uhd_find_devices                             # B210 在位核对（真机演示前跑）
```

启动网页操控台（演示主界面，全程只用鼠标）：

```bash
cd fn_work
.venv/bin/python -c "from src.serve_console.serve_console import serve_console; serve_console({'scenario_dir': 'scenarios', 'report_root': 'runs', 'port': 8000, 'dry_run': False})"
# 浏览器打开 http://localhost:8000/pages/index
```

### 0.5 演示前准备（一键物料）

出发前一天在主机上跑一次（预置演示场景＋预跑历史运行，让操控台的报告中心/录音库/AI 页有数据可翻）：

```bash
cd fn_work
.venv/bin/python -c "
from src.prepare_demo_assets.prepare_demo_assets import prepare_demo_assets
import json; print(json.dumps(prepare_demo_assets('scenarios', 'runs', rounds=3), ensure_ascii=False, indent=1))"
```

预期现象：输出 JSON 报告——`written` 列出 7 个预置场景、`prewarm_runs` 列出预跑运行目录（退出码 0 与 1 混合属正常：1=测到失效=核心产出）、`checklist` 含两档设备勾选表、`env` 含环境探测结果。重复执行不会破坏已有物料（`conflicts` 如实列出、未授权不覆盖）。

预跑只写运行目录、不建数据集索引——录音库/数据页首次打开会提示「数据集索引未建」。补一步重建（0.4 的操控台已起好的前提下），命令式：

```bash
curl -X POST http://localhost:8000/api/dataset/rebuild
```

或页面操作式：浏览器打开 `http://localhost:8000/pages/data`（数据页），点「重建索引」按钮。

预期现象：返回/上屏 `index_status: ready`——`rebuilt`＝预跑轮数（`demo_record` 每轮落一条录音；其余未录音的预跑运行计入 `skipped` 属正常），数据页出现各录音轮卡片且「回放此条」按钮可点（可回放）。

### 0.3 连接方式（ASCII 图＋接线表）

**方案 A——默认演示态（sim 全流程，最常用）**：只需笔记本；B210 可不接（自动降级 sim 并如实标注）。

```
[笔记本] ── (无需任何射频连接；backend: auto/sim)
```

**方案 B——B210 真机（监测/注入演示，屏蔽盒口径）**：

```
                       ┌────────── 便携金属屏蔽盒 ──────────┐
 [笔记本]               │  [双频天线A](发射)    [双频天线B](监测) │
   │USB3                │      ▲                   ▲          │
   └── B210 CH1 ─MMCX转SMA─[30dB衰减器]──┘    B210 CH2 ───────┘
       （CH1 也可不接天线、直连 SMA 负载闭合，零空中辐射）
```

| 接口 | 线缆/部件 | 对端 | 说明 |
|---|---|---|---|
| 笔记本 USB3 口 | USB3 数据线 | B210 | 供电兼数据；插 USB3 口否则带宽不足 |
| B210 CH1（MMCX） | MMCX 转 SMA → **30dB 衰减器** → 双频天线A 或 SMA 负载 | 盒内 | 发射链必串衰减器（合规 ≤0dBm 口径） |
| B210 CH2（MMCX） | MMCX 转 SMA → 双频天线B | 盒内 | 监测天线，独立采集实际注入谱 |
| B210 GPS 口 | GPS/BD 有源天线 | 盒外窗口 | 时钟参考演示（可选） |

**方案 C——ESP32 WiFi 真链路（配合方案 B 的注入天线）**：

```
                       ┌────────── 便携金属屏蔽盒 ──────────┐
 [笔记本]               │ [ESP32#1(tx)] ⇄WiFi⇄ [ESP32#2(rx)]  │
   │USB(串口)           │     ▲干扰经盒内发射天线压制此链路▲    │
   └── ESP32#2 串口     └──────────────────────────────────┘
       （KPI 帧经串口上报：ESP,<seq>,<sent>,<err>,<retries>,<rssi>[*<校验和>]）
```

| 接口 | 线缆 | 对端 | 说明 |
|---|---|---|---|
| 笔记本 USB-A 口 | ESP32 USB 线 | ESP32#2（接收/上报节点） | 串口设备名 `/dev/ttyUSB0` 或 `/dev/ttyACM0` |
| ESP32#1/#2 | 各自 USB 供电 | 充电头/USB 集线器 | 发射节点无需串口 |

**方案 D——NRF24 真链路（复用两块 ESP32 作主控）**：

```
 [ESP32#1] ─SPI─ [NRF24L01#1] ⇄2.4G ESB⇄ [NRF24L01#2] ─SPI─ [ESP32#2] ─USB串口─ [笔记本]
            （发送+上报节点：PLOS/ARC 计数与 RPD 位随 NRF 帧上报）
```

| 接口 | 线缆 | 对端 | 说明 |
|---|---|---|---|
| ESP32 ↔ NRF24L01 | 杜邦线×7（3V3/GND/MOSI/MISO/SCK/CSN＋CE） | NRF24 模块 | 3.3V 供电，接线以固件 README 引脚表为准 |
| 笔记本 USB-A 口 | ESP32 USB 线 | ESP32#1（发送+上报节点） | 串口帧：NRF,<seq>,<sent>,<lost>,<retries>,<rpd> |

> 主机 USB 口分配建议：USB3 口固定给 B210；两个 USB-A 口给 ESP32 串口；其余接集线器。设备名以 `ls /dev/ttyUSB* /dev/ttyACM*` 实测为准。

# 第一部分 测评核心（第 1–5 章）

## 1. 一键测评

### 功能说明
一条命令完成从场景校验、后端选择、干扰样式、功率步进、三路采集、失效判定到报告生成的全流程；退出码即结论：0=跑完且未失效，1=测到链路失效（核心产出）或运行中断，2=场景写错。这是平台的心脏功能，其余功能都是它的展开。

### 所需设备与连线（便携档、全量档）
便携档：只需笔记本（模拟模式全流程，无任何射频连接）；若想现场展示真机加分位，按总章 0.3 方案 B 连接 B210（CH1→30dB 衰减器→盒内天线或负载、CH2 监测天线、USB3 到主机）。
全量档：便携档设备基础上，示波器/万用表用于现场排障备查，不参与本功能流程。

### 操作步骤（命令与参数）
```bash
cd fn_work
# ① 失效演示（推荐第一个跑的命令，约 1 秒）
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['--demo']))"
# ② 零失效变体（换自己的场景文件，判据调成 0.999 即恒不触发）
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_smoke.yaml', '--backend', 'sim']))"
```

### 预期现象
①末行摘要 `status=failed failure_levels=1 traceability=passed`、进程退出码 **1**——这不是故障，是平台测到了"链路失效电平"这一核心产出；`report=` 后的路径即本次报告。②末行 `status=completed failure_levels=0`、退出码 **0**。两次运行都在 `runs/<时间戳>/` 生成完整八件套（场景副本/kpi.csv/events.jsonl/monitor.csv/recordings/report.md/plots/run.log）。

## 3. 国标测法自动化（GB 42590 §5.11）

### 功能说明
照搬国标强制测法：干扰功率从"比被测链路信号弱 5dB"起步、每档加 5dB，直到链路失效（默认判据丢包率>10%）立即停发并记录**失效电平**——整份测试最核心的数字。失效即停=先停发射再收尾（安全铁律）。

### 所需设备与连线（便携档、全量档）
便携档：只需笔记本（模拟模式跑国标全流程）；真机位按总章 0.3 方案 B。
全量档：同便携档。

### 操作步骤（命令与参数）
```bash
cd fn_work
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_failure.yaml', '--backend', 'sim']))"
```

### 预期现象
末行 `status=failed failure_levels=1 traceability=passed`、退出码 **1**（测到失效=成功产出）；打开 `report=` 路径的报告，"失效电平对比"一节给出失效电平中位数（模拟口径样例为 -15.0 dB 一档；多轮对比见第 21 章报告页）。`events.jsonl` 里能看到功率一档一档爬升、判据触发即停的时间线。

## 5. 链路健康测量

### 功能说明
被测链路的三项健康指标：丢包率（PER）、重传计数、信号强度（RSSI）。不插硬件时用内置模拟链路（一条带"失效悬崖"的真实退化曲线：干扰越强丢包越多、到临界点陡然崩溃）；插真硬件时用 ESP32 WiFi 链路或 NRF24 数传链路（固件已随平台交付，串口吐 KPI 帧）。NRF24 天生读不到 RSSI，报告会如实注明。

### 所需设备与连线（便携档、全量档）
便携档：只需笔记本即可演示模拟链路退化。真机演示位（可选，按总章 0.3）：WiFi 链路=ESP32 两块入屏蔽盒对发 UDP、接收节点 USB 串口接笔记本（方案 C）；数传链路=两块 ESP32 各接一片 NRF24L01（SPI 七线：3V3/GND/MOSI/MISO/SCK/CSN+CE，引脚表见 fn_work/firmware/nrf24_link/README.md）、上报节点串口接笔记本（方案 D）。
全量档：便携档基础上加示波器（看固件侧信号）、万用表（查供电），调试备查。

### 操作步骤（命令与参数）
```bash
cd fn_work
.venv/bin/python -c "
from src.demo_sitl_bridge.demo_sitl_bridge import demo_sitl_bridge

```

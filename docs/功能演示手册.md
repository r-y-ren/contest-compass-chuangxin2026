## 设备边界：为什么清单里没有大型仪器

演示平台清单里看不到频谱仪、信号源、EMI 接收机这类大仪器——**不是缺设备，而是它们的位置由 B210 和软件顶替了**：

| 您以为需要的大仪器 | 实际由谁承担 | 真实性 |
|---|---|---|
| 信号源（发干扰） | B210 CH1（70MHz–6GHz、带宽 56MHz 内，经 30dB 衰减进屏蔽盒） | 真发射 |
| 频谱仪（看谱） | B210 CH2 独立监测天线 | 真采集（一期频段内） |
| EMI 接收机 / 13GHz 混频 / 程控衰减器 | 模拟后端（插槽就位，真仪表到位即插即换、无需改代码） | 模拟口径（报告如实标注） |

所以准确说法是：**清单设备=平台全部已实现功能的真实演示全集**（干扰注入/监测/双链路/录音/AI 真数据全部真机可演）；上表第三行的远期测量按设计以模拟口径演示。清单即全集，无需另借大仪器。

# 第一部分 测评核心（第 1–5 章）

## 1. 一键测评

### 功能说明
一条命令完成从场景校验、后端选择、干扰样式、功率步进、三路采集、失效判定到报告生成的全流程；退出码即结论：0=跑完且未失效，1=测到链路失效（核心产出）或运行中断，2=场景写错。这是平台的心脏功能，其余功能都是它的展开。


### 操作步骤（命令与参数）
```bash
cd fn_work
# ① 失效演示（推荐第一个跑的命令，约 1 秒）
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['--demo']))"
# ② 零失效变体（换自己的场景文件，判据调成 0.999 即恒不触发）
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_smoke.yaml', '--backend', 'auto']))"
```

### 预期现象
①末行摘要 `status=failed failure_levels=1 traceability=passed`、进程退出码 **1**——这不是故障，是平台测到了"链路失效电平"这一核心产出；`report=` 后的路径即本次报告。②末行 `status=completed failure_levels=0`、退出码 **0**。两次运行都在 `runs/<时间戳>/` 生成完整八件套（场景副本/kpi.csv/events.jsonl/monitor.csv/recordings/report.md/plots/run.log）。

## 2. 六类干扰样式

### 功能说明
单音（CW）、扫频、线性调频（chirp）、带限噪声、部分频带、脉冲六类干扰波形全部软件生成，切换样式只改场景文件一个字段、不动任何硬件（实测切换毫秒级，指标要求 2 秒内）。超设备能力（带宽 56MHz 上限）的参数会被直接拒绝并说明原因。


### 操作步骤（命令与参数）
```bash
cd fn_work
# 练手场景 editor_practice.yaml 当前是带限噪声；把 style 依次改成
# tone / sweep / chirp / partial_band / pulse 各跑一轮（每轮约 3 秒）
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/editor_practice.yaml', '--backend', 'auto']))"
# 也可以在网页操控台的场景编辑器里改样式字段后「启动运行」（见第 20 章运行页）
```

### 预期现象
每轮 `status=completed`、退出码 0；同一场景只改 `style:` 一个字段即可连续演示六类（每轮约 5–6 秒）。模拟模式下各轮 `monitor.csv` 为同源合成底噪、不随样式变化——样式的差异看 `kpi.csv` 的丢包曲线与报告"样式识别"一节；监测频谱形状差异属真机（B210）演示位的表现；把带宽写成超限值（如 60000000）会被场景校验直接拒绝（退出码 2）并指明是哪个参数越界——可当"参数防线"小演示。

## 3. 国标测法自动化（GB 42590 §5.11）

### 功能说明
照搬国标强制测法：干扰功率从"比被测链路信号弱 5dB"起步、每档加 5dB，直到链路失效（默认判据丢包率>10%）立即停发并记录**失效电平**——整份测试最核心的数字。失效即停=先停发射再收尾（安全铁律）。


### 操作步骤（命令与参数）
```bash
cd fn_work
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_failure.yaml', '--backend', 'auto']))"
```

### 预期现象
末行 `status=failed failure_levels=1 traceability=passed`、退出码 **1**（测到失效=成功产出）；打开 `report=` 路径的报告，"失效电平对比"一节给出失效电平中位数（模拟口径样例为 -15.0 dB 一档；多轮对比见第 21 章报告页）。`events.jsonl` 里能看到功率一档一档爬升、判据触发即停的时间线。

## 4. 距离模拟

### 功能说明
"无人机飞远/飞近受扰会怎样"：把距离列表按标准对数距离损耗公式折算成干扰衰减台阶（参数 n/d0/l0 可调），一次跑完从远距微弱受扰到近距压制的整段演变；衰减能力范围外的距离点会被跳过并在事件流里记下原因，不假装测过。


### 操作步骤（命令与参数）
```bash
cd fn_work
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_distance.yaml', '--backend', 'auto']))"
# 场景内参数：distances: [1, 3, 7]（米）、model_params: {d0_m: 1, l0_db: 30, n: 2}
# 想演示"超上限跳过"：把 distances 加一个 100，重跑看事件流里的 skip 记录
```

### 预期现象
末行 `status=completed failure_levels=0`、退出码 0；`events.jsonl` 含 1/3/7 米各档的损耗-档位事件（距离越大=衰减越大=等效干扰越弱）。加入 100 米后该点被跳过并记录原因（当前硬件可模拟衰减约 50dB 上限），其余点照常完成——"如实标注、不虚构"的口径演示点。

## 5. 链路健康测量

### 功能说明
被测链路的三项健康指标：丢包率（PER）、重传计数、信号强度（RSSI）。不插硬件时用内置模拟链路（一条带"失效悬崖"的真实退化曲线：干扰越强丢包越多、到临界点陡然崩溃）；插真硬件时用 ESP32 WiFi 链路或 NRF24 数传链路（固件已随平台交付，串口吐 KPI 帧）。NRF24 天生读不到 RSSI，报告会如实注明。


### 操作步骤（命令与参数）
```bash
cd fn_work
# ① 模拟链路（先跑这个）：一轮零失效 + 一轮失效，对比 kpi.csv
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_smoke.yaml', '--backend', 'auto']))"
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_failure.yaml', '--backend', 'auto']))"
head -3 runs/<把上一轮时间戳填这里>/kpi.csv
# ② 真机链路（设备在位时）：先烧固件再以串口为 KPI 源跑场景——
#    烧录与监视命令见 fn_work/firmware/esp32_wifi/README.md（WiFi）
#    或 fn_work/firmware/nrf24_link/README.md（NRF24）
```

### 预期现象
①模拟侧：`kpi.csv` 八列 `timestamp_ms,link,source,per,judge_per,rssi_dbm,retries,per_note`（末列口径注记，可空）；失效轮的 per 随功率档爬升、到判据 0.10 一档陡增——"悬崖"形态。②真机侧：串口监视器每 500ms 吐一帧 `ESP,<seq>,<sent>,<err>,<retries>,<rssi>[*<校验和>]`（WiFi）或 `NRF,<seq>,<sent>,<lost>,<retries>,<rpd>`（NRF24，无 RSSI 属正常口径）；真机侧失效电平、PER 曲线等实测数字以现场为准（平台的数字纪律：实测前不预写）。

# 第二部分 记录、报告与 AI（第 6–10 章）

## 6. 三路同步记录

### 功能说明
被测链路指标（kpi.csv）、监测频谱（monitor.csv）、操作事件（events.jsonl）三路数据用同一主机单调时钟盖戳落盘——事后能精确对上"哪一刻加了干扰、哪一刻链路开始变差"，这是"干扰一加、链路立刻变差"这类因果论断的时间精度依据。


### 操作步骤（命令与参数）
```bash
cd fn_work
# 跑一轮带录音的场景后，看三路文件是否齐、时间戳是否同量纲
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['scenarios/demo_record.yaml', '--backend', 'auto']))"
ls runs/<时间戳>/          # 应见 kpi.csv / monitor.csv / events.jsonl / recordings/ 等
head -2 runs/<时间戳>/kpi.csv
head -2 runs/<时间戳>/monitor.csv
head -2 runs/<时间戳>/events.jsonl
```

### 预期现象
三路时间戳同一主机单调钟毫秒量纲（kpi/monitor 是 CSV 首列；events.jsonl 每行 ts 键）；kpi.csv 八列（`timestamp_ms,link,source,per,judge_per,rssi_dbm,retries,per_note`）、monitor.csv 为 `timestamp_ms,freq_mhz,power_db,confidence` 频谱流水、events.jsonl 每行一个操作事件（档位/启停/失效判定）。模拟口径下监测谱为合成底噪（真机位才是实际注入谱）——但三路对齐机制两种口径完全一致。

### 操作步骤（命令与参数）

```bash
    print(r)
except Exception as e:
    print('拒跑分支:', type(e).__name__, str(e)[:60])"
```

### 预期现象
带索引路径时走到数据面：`有效样本 N < min_samples=4（matched M 条，跳段 M 条）` 的如实拒跑——**归因注意**：只 rebuild 不 register 时全跳段的原因是 rebuild 条目不带样式标注（错误文案"IQ 段长不足"是平台提示文案的已知偏差，非真实原因），多攒录音不解锁，须按第 9 章 register 显式标样式。四阶段（取数/谱特征/分组 CV/部署模拟）演示的取数配方：**至少 2 类样式、跨至少 3 个 run_id** 显式 register（单样式会先撞"类别覆盖不足拒训"），攒够后逐段出 stage_progress 至 4/4 与产物清单。防泄漏评测口径与 AI 章（第 10 章）同族。

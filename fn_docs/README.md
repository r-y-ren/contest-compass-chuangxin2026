# 无人机链路抗干扰测试平台（用户手册）

> 面向使用者的完整说明：这个平台是什么、能做什么、每一步怎么用。
> 技术细节与验收口径见 requirements.md；功能全集与完成进度见《../docs/全功能实现清单-技术支持版.md》（已 100/100 ✅）。

## 这个平台是干什么的

我们自己搭两条小型无线链路（一块 ESP32 跑 WiFi、一块 NRF24 跑数传），当作"无人机通信链路"的替身。用一台软件无线电设备（USRP B210，可以理解为一台可编程的"信号发生器＋收音机"）按设定好的方式朝它们发干扰，全程记录链路表现变差的过程，最后自动出一份报告：什么样的干扰、多强的时候、链路坏到什么程度、机器认不认得这种干扰。

三句话记住它：

1. **一条命令出报告**——从发干扰到出带图的测评报告，全自动；
2. **不插硬件也能用**——软件自带"模拟模式"，用一台假想的 B210 走完全流程；
3. **以后买到新设备能像插积木一样直接加装**——每类仪表都有统一"插槽"，模拟器和真仪表是同一根插槽。

安全须知（软件里已写死，不用背）：只在屏蔽盒内做实验、发射功率不超过限值、只测我们自建的两条链路——报告里也会自动带上这些声明。

## 快速开始（三选一）

**前置依赖（第一次使用先装一次，全部装进虚拟环境，不动系统全局）**

```bash
cd fn_work
python3 -m venv --system-site-packages .venv    # 建虚拟环境（继承系统的 UHD 驱动绑定，SDR 驱动不重装）
.venv/bin/pip install -r requirements.txt       # Python 库装进 .venv，系统全局零污染
```

之后**所有命令都用 `.venv/bin/python` 开头**（不需要 activate，复制即用）。本仓库已带建好的 `.venv/`（不入 git）；换机器或删掉后按上面两行重建。

**方式一：一键演示（最简单，先跑这个）**

```bash
cd fn_work
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['--demo']))"
```

约 1 秒跑完。演示**特意安排在中段触发一次"链路失效"**，所以摘要行会是 `status=failed failure_levels=1`、退出码 1——这不是程序坏了，恰恰是平台的核心产出：**测到了失效电平**（对测评平台而言，"链路失效"是测出来的结果，不是故障）。想看"全绿不失效"的纯冒烟（退出码 0），用方式二把 `judge_per_threshold` 调成 `0.999`（阈值必须是 0–1 之间的小数，写 1.0 会被判无效）。

**方式二：自己的场景文件**

把测试意图写进一个文本文件（见下文「场景文件怎么写」），然后：

```bash
cd fn_work
.venv/bin/python -c "import sys; from src.run_demo.run_demo import run_demo; sys.exit(run_demo(['我的场景.yaml', '--backend', 'sim']))"
```

**方式三：网页操控台（全程只用鼠标）**

```bash
cd fn_work
.venv/bin/python -c "from src.serve_console.serve_console import serve_console; serve_console({'scenario_dir': 'scenarios', 'report_root': 'runs', 'port': 8000, 'dry_run': False})"
```

首次运行会自动创建 `scenarios/` 目录并自动生成页面。浏览器打开 `http://localhost:8000/pages/index`：场景卡片、滑杆调参、实时曲线、急停按钮、报告中心、清单完成度，全在页面上（Ctrl+C 关服务）。往 `scenarios/` 里放场景文件，卡片会自动出现。

## 工作流程（从开机到报告，每一步发生什么）

1. **准备**（可选）：把 ESP32 和 NRF24 用 USB 线接到主机，B210 接 USB3 线，天线按固定位置摆进金属屏蔽盒。只是演示或跑测试的话跳过，直接用模拟模式。
2. **装载场景**：软件读取你的场景文件，逐项检查——样式名是否在册、频率/功率是否超范围、频段是否在法规允许的无人机频段内（2.4G/5.8G）、两条安全声明（屏蔽盒、只测自建链路）是否带了。任何一项不过，直接拒绝并告诉你缺什么，实验不会开始。
3. **选择后端**：自动探测 B210 在不在——在就用真硬件；不在就切模拟模式，并在日志、网页和报告里标明当前用的是哪种。指定了后端但启动失败时，会明确报错并建议改用模拟模式，绝不偷偷降级。
4. **对时**：检查有没有高精度时钟（GPS 授时）可用，有就用，没有就用电脑时钟并在报告里注明。
5. **体检（基线守门）**：正式发干扰之前，先安静地听一段时间链路的表现。如果链路本来就不健康（比如丢包率已经很高），说明环境有问题，软件会中止并提示先排查——避免把环境问题误算成干扰的效果。
6. **正式测试**：按场景设定的方式发干扰——功率从"比链路自身信号弱 5dB"起步、每档加 5dB，一档一档往上试（这是照搬国家标准 GB 42590 规定的测法）。每一档期间同时盯三路信息：被测链路的健康指标（丢包率、重传、信号强度）、监测天线实际听到的干扰频谱、每一次功率调整的时间点——三路用同一个时钟盖戳，事后能精确对上"哪一刻加了干扰、哪一刻链路开始崩"。
7. **判定失效**：任何一档上丢包率超过 10%（行业判据，可自定义），立即判定"链路失效"，记下这一刻的干扰强度作为**失效电平**——这是整份测试最核心的数字。然后第一件事是闭嘴不发（安全铁律：任何出错、急停、正常结束，都是先停发射再干别的）。
8. **出报告**：自动汇总成 `report.md`——运行概要、三条曲线（丢包率随干扰强度的变化、吞吐变化、事件时间线）、失效电平对比表、干扰样式识别结果（如启用了 AI）、频谱图、缺了什么如实标注"缺"、以及四条口径声明（模拟部分已标注/非正式 EMC 认证/屏蔽盒环境/国标方法学预研定位）。
9. **数字体检**：报告里每个数字都会被自动回查一遍——它必须能在本次运行的原始数据文件里找到出处；查不到的会被点名。
10. **台账**：如果场景里指定了清单条目号（如 `ledger_entry: B1`），测试成功后会在《全功能实现清单》对应行自动打上 ✅ 完成标记。

**产物去哪看**：每次运行生成独立目录 `runs/<日期-时间>/`，里面有这些关键文件：场景副本（当时怎么设的）、kpi.csv（链路健康指标流水）、events.jsonl（每次操作的时间线）、monitor.csv（监测频谱流水）、recordings/（**默认为空目录**——场景写 `record: true` 才会存带"标准答案"标注的无线电录音）、report.md（报告，常规七个章节：概要/三条曲线/失效电平对比/样式识别/频点图谱位/缺项汇总/口径声明——EMC 场景会多一节）、plots/（三张曲线图）、run.log（全程日志）、result.json（运行结果汇总——含溯源结论与失效详情）、monitor_stats.jsonl（频谱统计流水）。出问题时先看 result.json 和 run.log。

## 项目功能（每项是什么、具体表现、怎么用）

### 测评核心

1. **一键测评**：一条命令完成第 5–9 步全流程；退出码 **0 = 跑完且未失效 / 1 = 运行中断，或国标测法测到了链路失效（核心产出）/ 2 = 场景写错**——自动化验收时：想以"零失效"为通过口径，把场景的 `judge_per_threshold` 设为 `0.999`（必须小于 1）即可恒得 0。
2. **六类干扰样式**：单音（一根频谱峰）、扫频（频率来回扫）、线性调频 chirp（雷达式斜坡）、带限噪声（一段频段里的杂音）、部分频带（只占被测带宽的一部分）、脉冲（间歇性开关）。全软件生成，切换不用动硬件，实测毫秒级（指标要求 2 秒内）。带宽自动限制在设备能力内（56MHz），想要造不出的波形会被直接拒绝并说明原因。
3. **国标测法自动化（GB 42590 §5.11）**：干扰强度"−5dB 起步、5dB 一档、直到链路失效"，整段流程照搬强制国标；测出的**失效电平**直接进报告。多音（复合）样式也支持。
4. **距离模拟**：想知道"无人机飞到 1 公里外受扰会怎样"？输入距离列表，软件按标准传播公式折算成干扰衰减量，一档一档试——从"远处微弱受扰"到"近处被压制"的演变一次看全。注意衰减能力有上限（当前硬件约 50dB）：超出上限的距离点会被跳过，并在事件流水里记一条"跳过+原因"，不会假装测过。示例距离建议取 1–10 米内。
5. **链路健康测量**：ESP32 链路看丢包率/重传/信号强度；NRF24 链路看丢包/重传（它天生读不到信号强度，报告如实注明）。没插真链路时，内置的模拟链路会用一条"真实的退化曲线"代替——干扰越强、丢包越多，到临界点陡然崩溃，和真实现象同形。

### 记录与报告

6. **三路同步记录**：链路指标、监测频谱、操作事件三路数据盖同一个时钟戳；报告里附"对齐误差"统计（中位数/95 分位），证明"干扰一加、链路立刻变差"这种因果论断的时间精度。
7. **自动报告**：见工作流程第 8 步——八节结构，缺什么标什么，绝不编数字。
8. **数字溯源校验**：报告里每个带单位的数字（dBm/MHz/百分比等）都会回查原始数据文件；手改过的数字会被当场点名。这让报告可以放心拿去给导师/评审看。
9. **带答案的录音库**：每次实验的原始无线电信号连同"当时发的是什么干扰、多强"的标注一起存档（业界通用格式）。攒得越多，越是一套公开数据里买不到的"带标准答案题库"。

### AI 识别

10. **AI 认干扰**：用录音库训练一个"看图认干扰"的模型（七分类：六种样式＋无干扰）。训练可以派发到远程显卡机跑，没有显卡也能本地跑个轻量版；评测按"同一批录音不跨组"的严格口径防止分数虚高——如果数据划分方式会夸大准确率，软件会自动检测并警告。识别结果直接进测评报告。

### 模拟与扩展

11. **EMC 电磁兼容摸底（模拟版）**：传导（沿电源线）和辐射（空中）两条摸底流程先用模拟仪表走通——限值线对比、余量计算、频段扫描、杂散标记，所有读数都带"模拟"标注。真接收机到位后换插槽即测。
12. **远期仪表模拟**：1433D 信号源、RSA513A 频谱仪、13GHz 混频扩展、EMI 接收机、程控衰减器——五台"未来的仪表"各有软件替身，清单里标"远期"的条目现在就能在模拟模式下走完全流程演示，真仪表买到即插即换。
13. **三种后端自动切换**：真硬件 B210 / 模拟 sim / 录音回放 replay。回放模式能把历史实验的数据流重新放一遍，用于复现和教学。

### 安全与台账

14. **安全红线内置**：功率上限、法规频段白名单、环境声明三道检查写死在软件里，违规配置一律拒绝且无法跳过；急停按钮/接口第一动作永远是停发射。这是设计红线，不是提醒。
15. **清单台账**：`update_ledger` 给《全功能实现清单》条目自动打 ✅（表格没有状态列时会自动补一列，不破坏原文）；`audit_ledger` 做体检——打了 ✅ 的条目其锚定的代码是否真实存在、注释率是否达标（当前 35.9%，目标 20%）。本周期 100 条已全部 ✅。

### 二期进阶（已可用，偏演示）

16. **飞行模拟器联动**：把实测的"干扰强度→丢包率"关系注入 ArduPilot 飞行模拟器，让模拟飞机体验真实链路退化（需装 pymavlink，没装会自动跳过不报错）。
17. **AI 自动出干扰策略**：用强化学习（一种让程序自己试错学策略的方法）在模拟环境里学"怎么发干扰最有效"，学不会时自动退回固定策略。
18. **设备指纹识别**：认出"这段信号是哪台设备发的"——训练、防泄漏评测、本机部署模拟的完整管道。

## 场景文件怎么写（完整可抄模板）

```yaml
# —— 必填 ——
style: tone                  # 六类任选，或 composite + components 列表
fs: 1000000                  # 采样率
bands: [[2400, 2483.5]]      # 工作频段（法规白名单内）
shielded_box: true           # 安全声明一：屏蔽盒环境
dut_scope: self_built        # 安全声明二：只测自建链路

# —— 常用可选 ——
freq_hz: 2450000000          # 中心频率
power_dbm: -15               # 功率（≤0，超了直接拒）
scenario_type: gb42590       # 四种：gb42590 / distance / custom / emc
judge_per_threshold: 0.10    # 失效判据（丢包率超过它算失效）
dwell_s: 0.5                 # 每档停留秒数
backend: sim                 # auto / b210 / sim / replay
record: true                 # 存录音
baseline_samples: 10         # 体检窗口样本数

# —— distance 类型专用（l0 取 30 时 1/3/7 米全部可达；超上限的点会被跳过并记录原因） ——
# distances: [1, 3, 7]
# model_params: {d0_m: 1, l0_db: 30, n: 2}

# —— 台账联动（路径自动锚定仓库根的清单；已 ✅ 的条目会跳过并提示；
#      想在实验清单上练手，加启动参数 --ledger /tmp/我的清单.md） ——
# ledger_entry: B1           # 测试成功后给清单 B1 打 ✅
```

## 常见问题

- **报"场景校验未通过"**：看错误清单第几条——缺声明/超功率/超频段/样式拼错都会列明（样式名检查在前，过了才查数值域）。
- **报"样本不足拒训：查询匹配 0 条"**：训练 AI 需要先有录音——用带 `record: true` 的场景多跑几轮（攒够 20 条以上），再训练。
- **报"远程算力不可达"**：训练默认走远程显卡机；没有就加 `where='local'` 参数本地轻量训练。
- **报 No module named 'fastapi' 之类**：你用的是系统 python 而不是虚拟环境——命令开头换成 `.venv/bin/python` 即可。
- **真机没反应**：先跑 `uhd_find_devices` 看设备枚举；被其他程序占用时设备段会消失，关掉占用程序即可。
- **报告里标了"缺项"**：说明那一节数据源为空（比如没触发失效就没有失效电平表），是如实标注不是故障。
